# Feature Coverage Map

This map links the app's major product and operational flows to their current
tests, docs, performance checks, and owning areas. Use it before adding new
validation, opening a release checklist, or generating ClickUp follow-up work.

Coverage strength:

- Strong: focused automated coverage plus at least one broad E2E, performance,
  release, or docs gate.
- Covered: focused automated coverage exists, with broad smoke or documented
  validation available when risk is higher.
- Partial: useful coverage exists, but at least one dimension depends on manual
  review, broad smoke only, or adjacent workflow checks.

## Maintenance Rule

When a PR adds, removes, renames, or materially changes a flow, validation
harness, workflow, release report, artifact path, or maintainer command, update
this map in the same PR. Prefer strengthening an existing row over adding a
parallel note. If a flow remains `Partial`, describe the missing automated or
live ownership path in the row instead of creating a broad follow-up task.
